PROJECT: NOTICIARIO

## 1. PROJECT OVERVIEW

Project name: Noticiario.

Goal:
Noticiario is a Laravel 13 + Inertia + React + TypeScript platform for creating short digital news bulletins from editorial planning to production-ready scripts.

High-level workflow:
1. Configure bulletin/schedule.
2. Create run.
3. Generate prompt.
4. Generate or paste AI response.
5. Parse response.
6. Create script.
7. Review/fact-check.
8. Verify sources.
9. Approve script.
10. Prepare production metadata.
11. Later audio/video/publishing.

Simplified product model for current Editor production work:
Informativo / Bulletin Type -> Programacion -> Ejecucion -> Guion / Script.

Internal prompt runs still exist because they store generated prompts, AI responses, provider metadata and debug traces, but they are secondary/detail records. The Editor user mental model should stay focused on the product flow: informativo, recurring schedule, concrete execution and generated guion. Sources, review and production readiness follow the guion stage.

Audio generation, video generation and publishing are future stages. They must stay visible as roadmap/placeholder concepts, but should not be implemented inside Editor prompt/script readiness branches unless the branch explicitly targets those stages.

## 5E. EDITOR GROUNDED BULLETIN FLOW

- Editor Bulletin Prompt Run flow now reuses grounded-provider selection logic consistent with pipeline behavior.
- Current-news bulletins (metadata grounded/current-news flags) require a grounded-capable provider and no longer silently fall back to Groq.
- Normal Editor execution resolves the AI provider from `BulletinType::preferredAiProvider()` / `bulletin_types.preferred_ai_provider_id`.
- Do not use a fake `BulletinType::aiProvider()` relationship or `bulletin_types.ai_provider_id` for the Editor bulletin/dashboard flow.
- If a bulletin has no preferred provider, normal Editor AI generation must fail clearly with "No AI provider configured for this bulletin."
- Groq remains available for explicitly assigned non-grounded text tasks, rewrites, debugging and low-cost auxiliary generation, but should not be silently selected for current-news grounded bulletins.
- Editor AI response generation now stores provider/model selection and AI response metadata on the prompt run metadata.
- Grounded AI metadata is now used by source extraction to create/link `SourceReference` records (pending verification) when URLs are provided.
- When grounded metadata has no extractable URLs, script flow can continue while preserving warnings in workflow metadata/UI.

  - `php artisan test --env=testing`

  - names containing `_testing`

  - `php artisan noticiario:check-test-database --env=testing`
- Composer safe script:
  - `composer test:safe`
- Recommended MySQL setup command:
  - `CREATE DATABASE IF NOT EXISTS noticiario2_testing CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;`

## 21. EDITOR HOME TIMELINE AND BULLETIN ON/OFF FOCUS (May 2026)

- Bulletin-level ON/OFF is now the visible operational switch for Informativos:
  - Effective ON = `bulletin_types.is_active = true`, a valid active usable/primary schedule, and complete activation configuration, so the informativo may be scheduled and run.
  - Raw `bulletin_types.is_active = true` alone is not enough for the Editor list or Dashboard to show the informativo as ON/runnable.
  - OFF = `bulletin_types.is_active = false`; its schedules are also turned off and ignored by cron.
- Activation is guarded. An informativo cannot be turned ON until it has:
  - assigned active AI provider,
  - valid primary/usable schedule with frequency, time and timezone,
  - location,
  - category,
  - language,
  - target duration.
- Turning an informativo OFF updates the bulletin and disables its schedules in one action. Turning it ON only reactivates a valid schedule; invalid or incomplete schedules are not blindly enabled.
- The automatic schedule runner now requires both `editorial_schedules.is_active = true` and `bulletin_types.is_active = true`, so OFF informativos are not eligible for automatic due-run creation.
- Editor > Informativos now separates rows into:
  - Informativos encendidos / Active bulletins,
  - Informativos apagados / Inactive bulletins.
- Missing configuration is shown with compact pills such as missing provider, schedule, location, category, language or duration.
- The Editor Dashboard `Informativos programados` section now shows only active, complete, scheduled informativos. OFF/inactive informativos are hidden from this dashboard section.
- The dashboard timeline is a horizontal daily diagram for the current day, spanning 00:00 to 23:59. It is built from real schedule runs for today plus active upcoming scheduled runs for today; inactive/OFF informativos are excluded.
- If there are no scheduled executions today, the dashboard shows a clean empty state.
- The existing editorial world map is embedded again on the dashboard using the existing map service/markers, with a direct action to the full Editor map.
- Main dashboard sections are collapsible accordions. Open/closed state is stored locally in `localStorage` under `noticiario.editor.dashboard.accordions`; no database preference migration was added.
