PROJECT: NOTICIARIO

IMPORTANT:
Keep this file updated after every major branch or feature.

Goal:
Noticiario is a Laravel 12 + Inertia + React + TypeScript application for creating short digital news bulletins. The platform helps editors collect and organize news by location/topic, prepare editions, and build scripts. Future phases may include AI-assisted planning, audio/video generation, and publishing automation.

Architecture:
- Laravel 12
- Inertia
- React
- TypeScript
- Tailwind
- MySQL
- Spatie Laravel Permission
- No Blade application pages
- resources/views/app.blade.php is only the Inertia root view
- React pages live in resources/js/Pages
- React layouts live in resources/js/Layouts

Panels:

- URL: /admin
- Permission: admin.access
- Purpose: technical/system administration
- Modules:
  - Dashboard
  - Users

EDITORIAL SCHEDULES AND MANUAL AI WORKFLOW

New database tables:
- editorial_schedules
  - Defines reusable schedule configurations (daily/weekly/once/custom), editorial context, language/location/category, timing, manual AI mode, and instruction blocks.
- editorial_schedule_runs
  - Represents concrete workflow executions created from schedules and linked to editions/scripts.

Purpose:
- Schedules let editors configure recurring and one-off noticiario planning templates.
- Runs provide the operational unit for each execution cycle (prompt generation, manual AI response capture, and script draft creation).

Manual AI mode workflow:
1. Configure schedule.
2. Create run.
3. Generate prompt.
4. Copy prompt to external AI.
5. Paste AI response.
6. Create script draft.

EDITORIAL SCHEDULES, RUNS AND DASHBOARDS

Database:
- editorial_schedules: configurable recurring and one-off planning definitions with location/category/language/tone/timing and manual AI instructions.
- editorial_schedule_runs: concrete executions linked to schedule, edition, optional request and script, with status lifecycle and prompt/response snapshots.

Purpose:
- Schedules define what should run and how the bulletin should be produced.
- Runs track the operational lifecycle for each execution and maintain audit/context metadata.

Manual AI mode:
- Prompt is generated by the platform and copied manually into external AI tools.
- Response is pasted manually back into the platform.
- Platform converts response into draft script linked to edition/run.

Dashboards:
- Editor dashboard now acts as the operational desk overview with today's tasks and action queues.
- Editorial Desk page provides a focused expanded workflow board.
- Admin dashboard provides system/technical overview plus editorial health indicators.
- Viewer dashboard provides read-only overview of completed scripts/runs and upcoming editions.

Workflow:
1. Configure schedule.
2. Create run.
3. Generate prompt.
4. Copy prompt to external AI.
5. Paste response.
6. Create script draft.

Demo data:
- Demo schedules include Spain 08:00/15:00/21:00, Madrid weekdays 09:00, Spain sports 20:00, and Super Bowl special.
- Demo runs include pending/prompt-ready/response-received/script-created examples for dashboard visibility.

Routes/pages:
- editor.dashboard (operational overview)
- editor.editorial-desk.index
- editor.editorial-schedules.*
- editor.editorial-schedule-runs.index/show + action routes
- admin.dashboard (system + editorial overview)
- viewer.dashboard (read-only overview)

Current limitations:
- No automatic AI calls yet.
- No cron/scheduler yet.
- No queue workers yet.
- No audio/video/publishing automation yet.
