PROJECT: NOTICIARIO

IMPORTANT:
Keep this file updated after every major branch or feature.

Goal:
Noticiario is a Laravel 12 + Inertia + React + TypeScript application for creating short digital news bulletins. The platform helps editors collect and organize news by location/topic, prepare editions, and build scripts. Future phases may include AI-assisted planning, audio/video generation, and publishing automation.

- Inertia

- TypeScript
- Tailwind

AVATAR DISPLAY PIPELINE

1. File is uploaded to:
   storage/app/public/media/images/users/{id}/...

2. media_files record stores:
   - disk = public
   - path = media/images/users/{id}/file.jpg
   - url can be null

3. users.profile_image_id must point to media_files.id.

4. MediaFile public_url is generated from:
   Storage::disk(disk)->url(path)

5. User avatar_url uses:
   - profileImage.public_url
   - avatar_path fallback
   - null fallback

6. Inertia auth.user must include:
   - avatar_url
   - initials
   - profile_image_id

7. React layouts use:
   - UserAvatar with auth.user.avatar_url

8. Public files require:
   php artisan storage:link

PROMPT QUALITY AND AI RESPONSE PARSING

What was improved:
- Editorial schedule run prompt generation now includes stronger guidance for factuality, recency, source hints, uncertainty handling, short presenter-ready paragraphs, and strict response structure.
- The default expected external AI response format is now structured plain text:
  - TITLE
  - INTRO
  - NEWS ITEMS with repeated HEADLINE/SUMMARY/SCRIPT/EDITORIAL ANGLE/SOURCE HINTS blocks
  - OUTRO
  - NOTES
- Prompt language instruction now explicitly tells the external AI to answer in the configured schedule language.

AiResponseParser service:
- New service: app/Services/EditorialScheduling/AiResponseParser.php
- Method: parse(string $responseText): array
- Handles English and Spanish label variants, including:
  - TITLE / TÍTULO
  - INTRO / INTRODUCTION / ENTRADILLA
  - NEWS ITEMS / ITEMS / NOTICIAS
  - HEADLINE / TITULAR
  - SUMMARY / RESUMEN
  - SCRIPT / GUION
  - EDITORIAL ANGLE / ENFOQUE EDITORIAL
  - SOURCE HINTS / FUENTES
  - OUTRO / CIERRE
  - NOTES / NOTAS
- Deterministic and tolerant parser behavior.
- Safe fallback for unstructured responses:
  - title=null, intro=null, outro=null, items=[]
  - body=full response text

Storage on editorial_schedule_runs:
- Added nullable JSON fields:
  - parsed_response
  - parser_warnings
- On AI response save:
  - ai_response_text is stored
  - response is parsed and stored in parsed_response
  - warnings are saved when structure is missing
  - response_received_at is set
  - status becomes response_received

Script creation from parsed response:
- If parsed_response contains useful structure:
  - script.title uses parsed title (fallback to edition title)
  - script.intro/outro are filled from parsed content
  - script.body is assembled from parsed items for presenter-ready flow
  - metadata includes parsed_response_used, news_item_count, and flattened source_hints
- If parsing is weak/unstructured:
  - fallback to previous behavior with full ai_response_text in body
  - parsed_response_used=false
- Existing script duplication is avoided (if script already exists for run, it is reused).

Editorial Run UI preview:
- Run show page now includes parsed response preview:
  - parsed title/intro/body/outro/notes
  - parsed items with headline/summary/script/editorial angle/source hints
  - parser warnings
  - raw response fallback preview
- Includes clear fallback messaging when no structured sections are detected.

Prompt template seeds:
- Updated seeded templates using updateOrCreate without deleting existing templates:
  - Manual AI Research And Script Prompt
  - Spanish Noticiario Prompt
  - Sports Special Prompt
- expected_output_format updated to structured_text for these templates.

Demo data updates:

- Seeding remains idempotent via updateOrCreate.

MANUAL FACT-CHECK AND SCRIPT REVIEW

Overview:
- Added a manual editorial review and fact-check layer on top of existing script status flow.
- This workflow is designed for human review before any automated AI/audio/video/publishing steps.

Scripts review fields:
- Added review_status (default: pending).
- Added review_notes and fact_check_notes.
- Added reviewed_by/reviewed_at.
- Added rejected_by/rejected_at/rejection_reason.
- Kept existing status + approved_by/approved_at behavior and used review_status as a parallel editorial layer.

script_review_items table:
- New granular review table linked to scripts.
- Supports optional link to news_items.
- Stores type, content, source_hints, verification_status, verification_notes, required_action, reviewer/timestamp, and metadata.

Purpose of review items:
- Allow editors to review each script section independently.
- Support fact-check and source completeness checks at block/item level.
- Enable clear manual workflow before final script approval.

Review statuses:
- pending
- in_review
- needs_sources
- needs_changes
- verified
- approved
- rejected

Verification statuses:
- pending
- verified
- needs_source
- needs_changes
- rejected
- not_applicable

Required actions:
- add_source
- rewrite
- remove
- check_date
- check_claim
- none

ScriptReviewItemGenerator service:
- New service: app/Services/EditorialReview/ScriptReviewItemGenerator.php
- Deterministically generates review items without AI/external calls.
- Prefers parsed metadata items when available.
- Otherwise splits body by double new lines and falls back safely.
- Optionally links edition news items to review items.
- Prevents duplicate generation unless force regeneration is requested.

Script Review page:
- New page: Editor/Scripts/Review
- Includes script header/status summary, counters, script-level review notes, per-item verification controls, and workflow actions.
- Supports generate items, mark in review, mark verified, approve, and reject (with required reason).

Approval/rejection workflow:
- Verified only when unresolved blocking item states are absent.
- Approval allowed when review_status=verified or all items are verified/not_applicable.
- Rejection requires rejection_reason.
- Approval/rejection also updates legacy script status to preserve previous workflow compatibility.

Relationship with AI-generated/manual scripts:
- Works for manually written scripts and scripts created from manual AI response parsing.
- No AI call is required for review item generation.

SOURCE VERIFICATION WORKFLOW

Overview:
- Added a manual source verification workflow for scripts, script review items, and news items.
- This workflow is fully manual: no external calls, no scraping, and no automatic URL verification.

source_references table:
- New table: source_references
- Stores editor-managed source references tied to:
  - news_items (optional)
  - scripts (optional)
  - script_review_items (optional)
  - editorial_schedule_runs (optional)
- Includes title, source_name, source_url, source_type, verification_status, trust_level, checked_by/checked_at, notes, metadata, timestamps, and soft deletes.

Purpose of source references:
- Track the specific references editors use to validate claims.
- Make source quality visible during script review and approval.
- Surface weak/missing/broken/rejected references before approval.

Source types:
- web
- official
- agency
- social
- rss
- manual
- unknown

Verification statuses:
- pending
- verified
- weak
- missing
- broken
- rejected
- not_required

Trust level:
- Numeric editorial trust score (manual).
- Intended for desk-level confidence scoring and prioritization.

Model relations:
- Script hasMany sourceReferences.
- ScriptReviewItem hasMany sourceReferences.
- NewsItem hasMany sourceReferences.
- EditorialScheduleRun hasMany sourceReferences.
- SourceReference belongsTo checkedBy user.

SourceReferenceExtractor service:
- New service: app/Services/EditorialReview/SourceReferenceExtractor.php
- Extracts source hints from:
  - script metadata and text
  - script review item source_hints/content
  - parsed response structures and source sections (SOURCE HINTS, FUENTES, SOURCES)
- Extracts URLs via regex.
- Deduplicates safe re-runs and avoids duplicate inserts.

Source References pages:
- Editor/SourceReferences/Index
- Editor/SourceReferences/Show
- Supports filtering, listing, detail/edit form, verification updates, and linked content navigation.

Script Review integration:
- Review page now shows linked source references per review item.

- Approval now blocks when source references include missing/broken/rejected states.

Script Show and News Item integration:
- Script show includes source summary and quick actions to extract/manage sources.
- News item show surfaces source references and allows creating a source reference from source_url.

Dashboard integration:
- Added source verification cards:

## BULLETIN PROMPT TIME WINDOW AND QUALITY

- Bulletin types now include explicit prompt timing and quality fields:
  - coverage_mode
  - coverage_starts_offset_minutes
  - coverage_ends_offset_minutes
  - coverage_description
  - include_future_agenda
  - include_historical_context
  - min_news_items
  - max_news_items
  - prompt_language
  - output_mode
- Coverage modes:
  - previous_period
  - today_so_far
  - yesterday
  - last_24_hours
  - next_24_hours
  - custom
  - none
- Coverage offsets are always relative to `scheduled_for`.
- `scheduled_for` fallback behavior:
  1. use explicitly submitted run datetime when provided
  2. else use bulletin type default_schedule_time in default timezone for current day
  3. else use current datetime
- Prompt generation now enforces broadcast timing context in all normal runs:
  - broadcast date
  - broadcast time
  - timezone
  - coverage window mode/from/to
- `prompt_language` controls the language used to instruct the external AI.
- Bulletin language remains the target language of the final script output.
- Output modes:
  - `plain_script`: ask only for presenter-ready clean text
  - `structured_script`: ask for structured sections (TITLE/INTRO/NEWS ITEMS/etc.)
- News count guidance:
  - use configured min/max when present
  - otherwise infer from duration: 60s => 3-4, 90s => 4-5, 180s => 5-8, above => 7-10

Examples:
- Morning: previous day 08:00 to today 07:30.
- Afternoon: today 08:00 to 14:30.
- Night: today 15:00 to 20:30.
- Preview: next 24 hours.

parsed_response JSON structure (saved on bulletin_prompt_runs.parsed_response):

- notes: string|null
- warnings: string[]
- raw: string

- Script creation falls back to full ai_response_text/raw response when no SCRIPT blocks are available.
- Existing scripts are never overwritten by updating the response or re-triggering script creation.

- missing_title
- missing_intro

- missing_sources
- unstructured_response

Source hints:
