PROJECT: NOTICIARIO

## 1. PROJECT OVERVIEW

Project name: Noticiario.

Goal:
Noticiario is a Laravel 13 + Inertia + React + TypeScript platform for creating short digital news bulletins from editorial planning to production-ready scripts.

High-level workflow:
1. Configure bulletin/schedule.
2. Create run.
3. Generate prompt.
4. Generate or paste AI response.
5. Parse response.
6. Create script.
7. Review/fact-check.
8. Verify sources.
9. Approve script.
10. Prepare production metadata.
11. Later audio/video/publishing.

Architecture:
- Laravel 13
- Inertia
- React
- TypeScript
- Tailwind
- MySQL
- Spatie Laravel Permission

Restrictions:
- No Blade application pages.
- resources/views/app.blade.php is only the Inertia root view.
- React pages live in resources/js/Pages.
- React layouts live in resources/js/Layouts.

## 5D. AUTOMATIC SCHEDULE RUNNER

- Added `App\Services\Scheduling\EditorialScheduleRunner` to detect due schedules and create schedule runs safely.
- Added command: `php artisan noticiario:create-due-runs` with options `--now`, `--dry-run`, `--schedule-id`, `--generate-prompts`, `--limit`.
- Runner now prevents duplicate runs for the same `editorial_schedule_id + scheduled_for`.
- Schedule flow now supports `schedule -> editorial_schedule_run -> bulletin_prompt_run` when configured with bulletin type.
- Prompt generation can be automatic (`auto_generate_prompt`) without calling external AI providers.
- Added scheduling fields including `next_run_at`, `last_run_at`, frequency/time/day settings and automation flags.
- Added editor actions: run now and recalculate next run from schedule detail page.
- Workbench and Editor Dashboard now surface due/upcoming schedule indicators and scheduler-created work counters.
- Automatic runner never calls external AI providers by default; `auto_generate_ai_response` remains disabled by default.

## GROQ PROVIDER SUPPORT

- Added first-class `groq` provider type using the existing OpenAI-compatible client flow.
- Groq base URL: `https://api.groq.com/openai/v1`.
- API key is resolved only via environment variable name `GROQ_API_KEY`.
- Never commit real API keys; provider records only store `api_key_env_name`.
- Configure/activate provider from Admin > AI Providers.
- Manual command for local checks:
  - `php artisan noticiario:test-ai-provider groq --dry-run`
  - `php artisan noticiario:test-ai-provider groq --prompt="Return exactly: OK"`
- Recommended manual test flow:
  1. Generate prompt in Bulletin Prompt Run.
  2. Choose Groq provider.
  3. Generate AI response.
  4. Inspect parsed response.
  5. Create script.
  6. Extract and verify sources.

## AI PROVIDER REQUEST NORMALIZATION AND GROQ FIXES

- AI provider numeric options are normalized before external calls.
- `temperature` is sent as a JSON number and `max_tokens` as a JSON integer.
- Empty/null numeric options are omitted from provider payloads.
- Groq continues using the OpenAI-compatible `/chat/completions` endpoint.
- Editor panel now uses an editor-safe AI request log route for logs related to the editor's own prompt runs.
- Prompt run failure UI now explains that no response was saved and points to safe log details.
- Spanish prompt headings are kept language-consistent (no mixed English workflow headings).
- API keys remain environment-only and are not exposed in logs/UI.
- Tests include numeric payload normalization coverage for Groq/OpenAI-compatible requests.
